# Markdown → DOCX dissertation compiler

Компилятор диссертации из связанных Markdown-заметок в оформленный DOCX.
Markdown остаётся источником текста, YAML хранит метаданные и правила
оформления, BibTeX — библиографию, а Obsidian используется как редактор и для
просмотра графа документа.

## Быстрый старт

```powershell
python -m pip install -e ".[dev]"
python build.py scaffold
python build.py validate
python build.py assemble
python build.py build
python build.py build-abstract
pytest
```

Основные команды:

- `scaffold` создаёт недостающую структуру диссертации;
- `validate` проверяет граф заметок, ссылки и подключаемые файлы;
- `assemble` раскрывает вложения в `build/assembled.md`;
- `build` выполняет полный цикл и создаёт DOCX по пути из
  `config/document.yaml`, автоматически добавляя очередной суффикс `-vN`.

Для сборки нужны Pandoc, а для PDF-приложений — Poppler. Настройки документа,
выходного файла, библиографии и CSL находятся в `config/document.yaml`;
сведения для титульного листа и структура глав — в `config/metadata.yaml`;
параметры оформления — в `config/styles.yaml`.

## Реализованные возможности

1. Графовая структура документа на основе `[[wiki-ссылок]]` и
   `![[трансклюзий]]`, включая вложение конкретного заголовка заметки.
2. Проверка дублирующихся идентификаторов, неоднозначных и отсутствующих
   ссылок до сборки.
3. Автоматическое создание четырёх глав и четырёх параграфов в каждой по
   умолчанию, а также преамбул, выводов по главам, введения, заключения,
   библиографии и приложений.
4. Автоматический титульный лист из YAML-метаданных без номера страницы.
5. Автоматическое оглавление Word с заголовками первого и второго уровней и
   без абзацного отступа у его строк.
6. Стили Word с Times New Roman, полями, интервалами и абзацами из YAML.
7. Редактируемые формулы Office Math, нумеруемые в пределах главы.
8. Таблицы из CSV, TSV и XLSX и рисунки из PNG/JPEG с подписями и нумерацией.
9. Динамические перекрёстные ссылки Word на формулы, таблицы и рисунки:
   закладки, поля `SEQ` для нумерации и кликабельные поля `REF` для ссылок.
10. Библиография из BibTeX по числовому CSL-стилю ГОСТ.
11. PDF-приложения, автоматически преобразуемые в страницы DOCX.
12. Совместимость исходников с Obsidian и его графом заметок.
13. Автоматическое версионирование сборок и архив предыдущих DOCX в
    `build/.old/`.
14. Максимальная полезная ширина страницы для рисунков и таблиц и единый
    Times New Roman во всех стилях Word.
15. Автоматические списки рисунков и таблиц с динамическими номерами страниц Word.
16. Списки сокращений и обозначений из единого файла `config/terms.yaml`.
17. Расширенная валидация директив, ресурсов, объектных ссылок и BibTeX-ключей.

## Автоматические списки

Файл `content/00 Front Matter/Списки.md` содержит четыре маркера:

```markdown
{{list:figures}}
{{list:tables}}
{{list:abbreviations}}
{{list:symbols}}
```

Списки рисунков и таблиц собираются из подписей объектов. Номера объектов и страниц
создаются полями `REF` и `PAGEREF`, поэтому после ручной перестановки материала в Word
их можно обновить вместе со всеми полями сочетанием `Ctrl+A`, затем `F9`.

Сокращения и обозначения редактируются в `config/terms.yaml`:

```yaml
abbreviations:
  - term: ASR
    definition: автоматическое распознавание речи
symbols:
  - term: Q
    definition: итоговая оценка качества преобразования
```

Команда `python build.py validate` дополнительно проверяет существование и тип файлов
таблиц и рисунков, обязательные подписи и идентификаторы, дубли объектов, ссылки на
несуществующие объекты, отсутствующие BibTeX-ключи и заметки, не включённые из
корневого документа. Неиспользуемые записи библиографии выводятся как предупреждения.

## Автоматическая статистика

В Markdown доступны числовые маркеры `{{stat:...}}`: `pages`, `chapters`, `figures`,
`tables`, `appendices`, `bibliography`, `publications`, `publications_vak`,
`publications_scopus_wos`, `publications_other`, `software_registrations` и `patents`.
Число страниц создаётся динамическим полем Word `NUMPAGES`; остальные значения
рассчитываются из структуры проекта, директив объектов и BibTeX. Для склоняемой формы
доступен маркер `{{stat_phrase:figures}}` — например, «1 рисунок» или «5 рисунков».

## Публикации автора и типы BibTeX

Научные источники хранятся в `bibliography/bibliography.bib`, а публикации автора,
патенты и регистрации программ — в `bibliography/publications.bib`. Обе библиотеки
доступны для цитирования, но показатели раздела «Публикации автора» считаются только
по второй. Классификация задаётся полем `keywords`: `vak`, `scopus`, `wos`, `other`,
`patent`, `software-registration`.

Валидатор поддерживает и проверяет обязательные поля для `article`, `inproceedings`,
`book`, `online`/`www`, `standard`, `patent`, `phdthesis`, `mastersthesis`, `techreport`
и `software`. Для записи с `url` обязательна дата обращения `urldate`. Повторяющиеся
DOI, ISBN и BibTeX-ключи являются ошибками.

## Расширенные приложения

Приложения могут одновременно содержать Markdown, таблицы, директивы `figure` и PDF.
Полный PDF встраивается как `![[assets/appendices/document.pdf|175mm]]`, отдельная
страница — как `![[assets/appendices/document.pdf#page=2|175mm]]`. Ширина после `|`
задаёт размер изображения страницы в DOCX. Валидатор проверяет наличие и непустой
размер PDF, диапазон выбранной страницы, предупреждает о файлах больше 50 МиБ и
контролирует непрерывный порядок приложений А, Б, В и далее.

## Структура диссертации

Параметры секции `structure` в `config/metadata.yaml` задают число глав,
параграфов и приложений. По умолчанию создаются четыре главы и по четыре
параграфа:

```text
Глава 1 → преамбула → 1.1 → 1.2 → 1.3 → 1.4 → выводы
Глава 2 → преамбула → 2.1 → 2.2 → 2.3 → 2.4 → выводы
...
```

`python build.py scaffold` создаёт отсутствующие заметки и обновляет только
служебные блоки ссылок. Уже написанный текст не перезаписывается. Общий файл
`content/root.md` подключает структурные разделы, главы, заключение, список
литературы и приложения. Файл главы, в свою очередь, подключает её преамбулу,
параграфы и выводы.

## Obsidian и формулы

Откройте `content/` как Obsidian vault. Локальная конфигурация использует
Wikilinks и абсолютные пути внутри vault, поэтому ссылка
`[[01 Chapter/1.2. Параграф]]` разрешается от каталога `content/`, независимо
от расположения текущей заметки.

Для предварительного просмотра формулу можно хранить в отдельной заметке:

```markdown
---
id: equation:loss
type: equation
---

$$
L(\theta) = -\sum_i y_i \log p_i
$$
```

Вставка `![[equations/loss]]` показывает формулу в Obsidian и переносит её в
собранный Markdown. Для нумеруемой редактируемой формулы DOCX используйте
директиву:

````markdown
```equation
id: quality
latex: Q = \alpha A + \beta C
```
````

В DOCX формула выравнивается по центру, а номер — по правому краю посредством
табуляции, без использования невидимой таблицы.

## Версии сборок

Каждый запуск `python build.py build` определяет наибольший номер версии в
`build/` и `build/.old/`, затем создаёт следующий файл, например
`dissertation-gost-title-v13.docx`. Только после успешной сборки предыдущие
версии перемещаются в `build/.old/`. Если старая версия открыта в Word и
заблокирована, она остаётся на месте, а сборщик выводит предупреждение и не
прерывает создание нового документа.

## Таблицы, рисунки и ссылки

Исходные данные таблиц хранятся в `content/assets/tables/`:

````markdown
```table
source: assets/tables/results.xlsx
sheet: Experiment
id: results
caption: Сравнение моделей
```
````

Поддерживаются CSV, TSV и XLSX. Для XLSX можно выбрать лист параметром
`sheet`. Рисунки PNG/JPEG хранятся в `content/assets/images/`:

````markdown
```figure
source: assets/images/pipeline.png
id: pipeline
caption: Мультимодальный конвейер обработки
width: 150mm
```
````

При сборке рисунки масштабируются с сохранением пропорций до полной полезной
ширины листа между полями. Таблицы получают ту же ширину и явную сетку колонок.
Параметр `width` сохраняется в исходном синтаксисе для совместимости и
предварительного просмотра, но итоговый профиль диссертации использует
максимальную ширину.

Объекты нумеруются независимо внутри каждой главы. Полная ссылка на формулу:
`{{ref:equation:quality}}`. Для согласования с русскими падежами вставляйте
только номер: `на рисунке {{number:figure:pipeline}}` или
`в таблице {{number:table:results}}`.

При сборке компилятор создаёт для каждого `id` закладку Word, номер объекта как
поле `SEQ` и ссылку как поле `REF \h`. Полная форма автоматически добавляет
слово «таблица»/«рисунок» или круглые скобки формулы; форма `number` возвращает
только номер. Ссылка кликабельна в Word. После ручной перестановки объектов в
готовом DOCX обновите номера и ссылки командой `Ctrl+A`, затем `F9`. Если объект
перенесён в другую главу в Markdown, заново выполните `python build.py build`.

## Библиография

Записи хранятся в `bibliography/bibliography.bib`, а ссылки вставляются в
синтаксисе Pandoc:

```markdown
Метод описан в работе [@vaswani2017attention].
Несколько работ рассматривают эту проблему
[@source4; @source5; @source6; @source7].
```

В список литературы попадают только процитированные записи. Подключённый CSL
сортирует числовую группу и сворачивает три и более последовательных номера:
`[4–7]`. Несмежные номера оформляются, например, как `[4,6–8,11]`. Для
устойчивости ссылок не изменяйте BibTeX-ключи после их использования в тексте.

## PDF-приложения

Приложения подключаются через `content/99 Appendices/Приложения.md`. PDF-файл
помещается в `content/assets/appendices/` и вставляется нативным для Obsidian
синтаксисом:

```markdown
![[assets/appendices/implementation-act.pdf]]
```

При сборке каждая страница PDF визуализируется с разрешением 200 DPI и
вставляется в DOCX с шириной 160 мм. Начиная со второй, страницы отделяются
разрывами. Отдельная страница подключается как
`![[assets/appendices/file.pdf#page=2]]`. Отсутствующий файл обнаруживается на
этапе проверки.

## План развития

Функции реализуются и документируются последовательно:

1. Автоматические перечни таблиц и рисунков.
2. Расширенные таблицы: объединение ячеек, повтор заголовка, продолжение и
   примечания.
3. Сноски и концевые примечания из Markdown.
4. Расширенные приложения: Markdown-приложения, несколько PDF и управление их
   подписями и нумерацией.
5. Усиленная предполётная проверка: отсутствующие ключи BibTeX, повторяющиеся
   идентификаторы объектов и неиспользуемые ресурсы.
6. Режимы черновой и финальной сборки и автоматическая визуальная проверка.
7. Автореферат на основе общих метаданных и материалов диссертации.
8. Презентация по структуре и результатам работы.

После реализации каждого пункта его описание и пример синтаксиса переносятся
из этого плана в раздел «Реализованные возможности».

## Ширина рисунков и PDF-приложений

В итоговом DOCX все встроенные рисунки и растрированные страницы PDF по умолчанию
занимают всю ширину между полями. Пропорции сохраняются; слишком высокое изображение
дополнительно ограничивается по высоте печатной области. После сборки размер можно изменить
в Word для отдельного объекта.

## Секции с разными полями

Профили секций задаются в `config/sections.yaml`. В нужном месте Markdown профиль включается
отдельной строкой:

```markdown
{{section:appendix-wide}}
```

Доступны готовые профили `dissertation`, `appendix-wide` и `landscape`. Каждое переключение создаёт
настоящий разрыв секции Word с новой страницы. Колонтитулы и нумерация продолжаются, а
рисунки и таблицы автоматически занимают ширину новой печатной области. Для возврата к
обычным полям используется `{{section:dissertation}}`.

## Общие данные диссертации и автореферата

Канонические научные утверждения хранятся в `content/_shared/research/`, а их роли и ID —
в `config/research.yaml`. Автореферат расположен в `content/80 Abstract/` и подключает общие
объект, предмет, цель, задачи, методы, положения на защиту, новизну, значимость, апробацию и
результаты через Obsidian-трансклюзии. Тексты краткого содержания глав остаются отдельными,
но содержат поле `source: chapter:N`; валидатор проверяет существование исходной главы.

Опубликованные работы находятся в `bibliography/publications.bib`. Неполные и ожидаемые записи
хранятся в `bibliography/publications.pending.yaml` и не участвуют в цитировании или счётчиках.
Формулы, рисунки и таблицы могут использовать общий стабильный `id`, но получают собственные
номера в каждом итоговом документе в соответствии с порядком включения.

## Реестр конференций и апробация

Конференции, семинары и другие мероприятия апробации хранятся отдельно в
`bibliography/conferences.bib`. Запись использует тип `@conference` и обязательные поля `title`,
`eventdate`, `location` и `talk`; дополнительно поддерживаются `organizer`, `award`, `url`,
`urldate` и `keywords`. Диапазон дат задаётся как `YYYY-MM-DD/YYYY-MM-DD`.

```bibtex
@conference{report2026,
  title     = {Название конференции},
  eventdate = {2026-02-16/2026-02-18},
  location  = {Коломна},
  talk      = {Название доклада},
  keywords  = {conference, national}
}
```

Маркер `{{list:conferences}}` формирует хронологический список мероприятий. Доступны также
`{{stat:conferences}}` и склоняемый `{{stat_phrase:conferences}}`. Один общий файл апробации
`content/_shared/research/Апробация.md` подключается и в диссертацию, и в автореферат.

## Сборка автореферата

Команда `python build.py build-abstract` собирает отдельный версионируемый DOCX из
`content/80 Abstract/Автореферат.md`. Параметры служебного разворота и поля для сведений о
защите находятся в `config/abstract.yaml`. Первые две физические страницы не нумеруются;
основной текст начинается с номера 1. Оглавление в автореферат не добавляется.

По умолчанию автореферат верстается как готовая брошюра A5: поля 15 мм, титульная
страница Times New Roman 11 пт, оборот титула 10 пт, основной текст 11 пт. Интервалы
между блоками обложки задаются в `layout.title_spacing`, а сведения об организации,
оппонентах, защите, библиотеке, сайте и учёном секретаре — в секции `defense`.

Текст краткого содержания глав хранится в `content/80 Abstract/Главы/`. Общие формулировки
подключаются из `_shared`, апробация — из `conferences.bib`, а список публикаций — из
`publications.bib`. Формулы, таблицы и рисунки, включённые в Markdown автореферата, получают
собственную последовательную нумерацию независимо от диссертации. Профиль задаётся в
`config/abstract.yaml`:

```yaml
numbering:
  objects: global
```

Значение `global` формирует номера `(1)`, `(2)`, ... для формул и сквозные номера для
рисунков и таблиц, даже если в автореферате используются заголовки вида `# Глава 1`.
Диссертация продолжает использовать номера по главам (`1.1`, `1.2`, `2.1`). Один и тот же
стабильный `id` разрешено использовать в обеих сборках: каждая получает собственные номера,
последовательности Word и пространство закладок. Ссылка `{{ref:equation:model}}` считается
ошибочной, если объект с таким `id` существует только в другом итоговом документе, но не
включён в текущий.
